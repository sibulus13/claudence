# Notion playbook (cue: any Notion MCP tool)
- Writes, deletes and moves run without a prompt (owner 2026-11-06); deletes go to Notion's Trash and stay restorable. Reads are free. The scheduled tiktok-sync job may update matched Content Bank rows (metrics, Status=Done, review body) unattended; nothing else.
- Add a database property only when a script joins on it or a person sorts/filters by it at a glance; everything else goes in the page body.
- Notion is the overview: status, question, result and links. Specs and technical detail stay in GitHub or the work tree, and each side links the other (owner 2026-11-06).
- Notion stores datetimes in UTC; the owner's time zone is America/Vancouver.
- Cortex runs use the claude.ai Notion connector with `--setting-sources project,local`, so global hooks do not apply to them; their own capability grants do.
- TODOs database: `Priority` is the owner's only, so leave it empty on rows you create. `This week` makes a row a weekly goal that Cortex schedules and reminds about; use `Backlogged` plus a due date for later work. Rules: Cortex `agents/chief-of-staff.md`, the TODOs schema section (owner 2026-11-07).
- TODOs hierarchy: a multi-step effort is one parent row with children through `Parent`. Tabs show top-level rows only, so set only the parent to `This week`; steps stay `Not started` or `Backlogged` with due dates. A view change goes in both the database and Dashboard copies (Cortex C56, C140).
- TODOs parent page: use the [To-do overview template](https://app.notion.com/p/4115eed4845d816db806f3563b5c42fa) (`apply_template` takes its page ID): Overview (Goal, Now, Next, Measure, Decided, Risk, Dates) with one diagram, Steps as a linked view filtered on `Parent`, Scorecard if measured, Links. Each fact has one home: due date and status on the step row, metric and drafts on the step page, rules on the parent, other diagrams and detail in the repo report. Don't list steps by hand or repeat the parent's name in a step's name.
