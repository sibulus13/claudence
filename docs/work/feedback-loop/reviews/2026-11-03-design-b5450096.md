   nothing builds; the proposal's own item 3 would be a second owner of the fold and probe-citation rules; F1 says
   Depends on "-"; the deferral "fold writes to the change spec's Timeline" points at a section v3 lacks. Fix: depend
   the fold and per-capability tally on a capability-layer item that owns them; cut F1 to the append-only gate; give
   Amendments rows ids (A-n).
2. F1's freeze contradicts agentic-loop editing the locked README (README.md:111,128 vs agentic-loop :171-186, :206).
   R, breaking: yes, new: cross-spec-contract-conflict, design. The Status column and generated chart colors change
   above Amendments after lock; AC-1 refuses them. A move back to draft (D41, spec_v3.py:197) must lift the freeze.
   Fix: progress state outside the frozen README (e.g. generated files the hash excludes) or a named exemption list in
   both specs; AC-1 exempts frontmatter status and a staged draft.
3. AC-3 has no regime marker (README.md:130,154). R, breaking: yes, arrival channel/compatibility, design. The gate
   cannot tell a pre-F1 lock from a post-F1 one; "has an Amendments heading" lets a new item lock without it and stay
   under D37; appending an escape row to a pre-F1 shipped item is an unlisted change under D37
   (WORK-ITEM-STANDARD.md:177). Fix: a frontmatter marker (e.g. `amendments: v1`) set at draft, required at lock,
   irremovable past draft; state how pre-F1 items adopt.
4. F3 does not close the loop (README.md:113,134,136). R, breaking: yes, new: no-closed-state, design. Proposals have
   no states, no owner definition, no read-back; duplicates forbidden so a stale proposal goes silent; no reopen after
   applied; RETRO-QUEUE.md is in the private fleet repo with no write path stated; no eval harness exists. Fix:
   proposal id and state, open count and age in the tally, reopen on recurrence after applied, /retrospect offers to
   close; targets narrowed to checklist lines and reviewer checks until an eval harness exists; AC-8 covers T2 only.
