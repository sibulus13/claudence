# Security review: pii-scan (fresh context)

Filed by the parent session: the reviewer's own write of this report was refused by the guard hook (a false positive on a scratchpad path), so the parent saved the reviewer's text verbatim.

Kind note: the contract allows only design, code and verify. `code` needs a REVIEWED-COMMIT, and the reviewed code is in no commit. Recorded as `design`, the closest kind that does not claim a commit.

Lifecycle: pre-traffic harness hook; runs on every commit in a repo with a `.pii-scan` marker (today only claudence, which is public); reads staged content and ~/.claude/private/pii_terms.txt.

Reviewed: the WORKING-TREE pii_scan.py and its tests (fix-round version), the staged README and probe, and the pii-scan hook block.

Runs: 13 passed (pytest tests/test_pii_scan.py). Real pre-commit 4.7.0 in a scratch repo, with the real script and a fake terms file. Refused as designed: a new email, a spaced term, a term wrapped across lines, a term joined by NBSP, `commit -a`, `commit <path>`, `--amend`, `git mv` plus an added term, and a force-added copy of the terms file. Everything below landed.

## Findings
1. Commit metadata (author and committer email, commit message) is not scanned. .pre-commit-config.yaml (pre-commit stage only); scripts/pii_scan.py main (scans file paths only). R. breaking: yes. Class A. Published history already carries personal author emails (owner decision). Fix: in the commit-msg stage, run `hits` on the message file and on `git var GIT_AUTHOR_IDENT` and `git var GIT_COMMITTER_IDENT`.
2. The refusal prints the matched term and the full email. H. breaking: no. A. Fix: name a term by its line number and mask the email's local part.
3. An empty terms file passes every term silently. F. breaking: no. C. Fix: treat zero terms as a missing file.
4. Spotify ID shapes missed: api.spotify.com/v1/users/<id>, open.spotify.com/intl-de/user/<id>, and spotify:user:<id> starting with _ or ".". R. breaking: no. C.
5. Agent bypasses the guard does not cover: `git commit -n`, `-c core.hooksPath=...`, `SKIP=pii-scan`, an empty file in PII_TERMS_FILE. R. breaking: no. C. A guard change is governance, so this is a proposal.
6. Content never scanned: types:[text]; UTF-16 files, PNG tEXt, PDF /Author, xlsx creator, %40 and &#64; emails, terms split by zero-width space, hyphen, underscore, camelCase or bold. R. breaking: no. C.
7. cherry-pick and merge --no-ff of a commit made without the hook both landed. R. breaking: no. C.

Most risk reduced by one change: a pre-push scan of the outgoing range (each commit's diff, message and author and committer ident). It covers findings 1, 5 and 7.
