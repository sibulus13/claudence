1. R (test; gap: new "mutant-survives / fixture does not exercise the rule"). tests/classification.tests.ps1, Describe fix-friction-system-prompts, AC-1 (around lines 349-380 of the file).
   - The join rules the spec names are not pinned. The sidechain skip, "each entry once", "nearest", the 5 s window and the text-prefix check can each be removed and all 18 tests stay green. `queued` also survives, although AC-1 says the fixture uses all five `promptSource` values and it has no `queued` entry.
   - Why they survive:
     - The sidechain entry (18:01:01) is never the nearest candidate, because 0.1 s beats 1.0 s.
     - The two "Go ahead" events are separated by 2 s, so nearest alone separates them. Nearest and `used` each mask the other's removal.
     - No entry lies outside 5 s.
     - Every event has a matching prefix, so no event ever meets a non-matching entry.
   - Failure scenario: someone makes the join take the first entry in the window, or drops `isSidechain`, or sets the window to a minute. A sidechain `typed` prompt then steals a system prompt's join and is scored as the owner's, and the suite is still green.
   - Fix: add cases where the sidechain `typed` entry is closest, an entry sits 6 s away so the event stays unlabelled, a nearer entry comes later in the entry order, one entry serves two identical events, a same-time entry has different text, and a `queued` entry exists.

3. R (implementation; gap: behaviour-regression of a derived field). telemetry/analyze-session.ps1:95 and :153.

   - Excluding that session from the rolling averages is intended.

4. F (implementation; gap: resource handling). telemetry/lib/classification.ps1:191.
   - `[System.IO.File]::ReadLines` opens with FileShare.Read. I confirmed that when another handle holds the file open for write, it throws an IOException and `Read-TranscriptPrompts` returns 0 entries.
   - The effect is a stderr exception and every prompt left unlabelled, so the live labels are kept. This is not silent, because `unlabelled` equals the prompt count in the report, but the fix is lost for that session.
   - Whether Claude Code holds the transcript open for write at Stop is unverified, so this is a suspicion about the other process; the .NET behaviour itself is verified.
   - Fix: open a FileStream with FileShare ReadWrite and Delete, wrapped in a StreamReader.
   - A missing transcript path returns `@()` correctly. I did not benchmark a very large transcript. The pre-filter on the literal `"promptSource"` is sound, and unparseable lines are skipped.

5. F (implementation; gap: unbounded cost against a timeout). telemetry/lib/classification.ps1:128-137.
   - The join is O(events × pool) and recomputes `Get-JoinKey` for every pair.
   - I measured 7.4 s for 642 events by 642 entries. 642 is the largest session in telemetry/sessions today (a 429-prompt session also exists), so it is close to the real worst case. A 300 × 1500 case took 16.3 s.
   - The Stop hook timeout is 30 s, with 3 s of other work added by the script. At about 1,200 or more owner prompts the hook is killed before the report, ledger and cumulative update are written.
   - Fix: precompute the entry keys once, and index or sort by time so the window narrows the candidates.

6. F (implementation; gap: boundary, empty or look-alike input). telemetry/lib/classification.ps1:131.
   - An empty join key makes `StartsWith('')` true, so it matches anything. I confirmed both directions:
     - An empty-text event (prompt_text `''`) joins a `system` entry within 5 s.
     - An empty-text entry (image-only content array, where `Read-TranscriptPrompts` yields text `''`) joins an unrelated event.
   - Failure scenario: an image-only typed entry takes the join of a nearby injected event, which is then scored as the owner's. This needs a coincidence within 5 s, which is why it is F.
   - Fix: require a non-empty key, or require exact equality when either key is empty.
