Findings

1. R. scripts/spec_gate.py:222-223 (`git_trailers`) and :238-240 (`message_body`). `core.commentChar=auto` makes a correct commit refuse, and the hint then gives wrong advice. Category: asserted-not-verified-claim, class: design.
   - Scenario: `git -c core.commentChar=auto commit -a -e -m $'feat: x\n\n#1 fix\n\nSpec: docs/work/demo/README.md\nCo-Authored-By: ...\nClaude-Session: ...'`. The same happens with `-v`. Git picks `;` because the body has a line starting with `#`.
   - The hook file then ends with a `;` comment block (and, under `-v`, a `; ---- >8 ----` scissors line plus the diff). I captured the file to confirm.
   - A separate `git interpret-trailers` process does not resolve `auto` and treats only `#` as the comment character. It therefore reads the `;` block as part of the last paragraph, so no trailer is found.
   - Wrong outcome: the commit is rejected with "A `Spec:` line was found but not read as a trailer: it is outside the final trailer block (git reads trailers only from the last paragraph, after a blank line)". The user's message is correct, so the advice is false. `message_body` also maps `auto` to `#` (line 240), so the revert check and the hint see the `;` lines and the diff as body text.
   - Control cases all landed: `auto` without a `#` line, `auto` with `-m` and no editor, and `#` with `-e -m`.
   - The `git_trailers` docstring says "git handles comments, core.commentChar and the commit -v scissors itself". That is false for `auto`. The work item's Expected line repeats it.
   - The old code failed the same way on `;` lines, so this is not a regression. The item claims to fix it, though, and no test covers it.
   - Suggested fix at the authoritative layer: take the comment character from the file (the `^(\S) -+ >8 -+$` scissors line, or the "Lines starting with 'X' will be ignored" line). Pass it as `-c core.commentChar=<c>` to `interpret-trailers` and use it in `message_body`. Add an AC and a test with `auto`, `-e` and a `#N` body line.
   - Arguably F, since `auto` is unusual config and the failure is loud (a rejection), not silent. I rate it R because the spec asserts git handles it, the repo's own gate runs on every commit, and the fix is cheap.

2. H. scripts/spec_gate.py:263 (the `others` computation in `trailer_hint`). Cause 1 treats an indented continuation line as a non-trailer line. Category: stale-or-wrong-diagnostic, class: implementation.
