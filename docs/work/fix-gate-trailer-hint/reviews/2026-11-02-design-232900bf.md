## 3. fix-gate-trailer-hint

Root cause confirmed by running git 2.39. I used a real `git commit -v` with an editor stub and a logging commit-msg hook.
- The hook file contains the comment template, the scissors line and the full diff, including lines like `--- /dev/null`.
- Default `git interpret-trailers --parse` on that raw file returns the `Spec:` trailer, because git handles the scissors and comments itself.
- The gate's own `#` strip removes the scissors line but leaves the diff, so the trailers are lost.
- `--no-divider` on the raw file still works.
- `-c trailer.separators='='` makes `Spec: x` vanish, so the pin in AC-6 is needed.
- `Specs:` parses as a trailer key, `spec:` parses case-insensitively, and an indented `  Spec:` and `Spec: p` plus a `🤖` line (2 lines, 1 trailer, no git-generated trailer) both yield nothing.

**1. R: the hint trigger is undefined, and Expected contradicts AC-5 (README:53, 62, 63).**
- Expected: "when a Spec:-shaped line exists that git does not read as a trailer, the rejection names why". AC-4: `Spec: <path> (building)` gets a "text after the path" hint.
- AC-5: `Spec: see the README for why` at a line start gets no hint.
- Both are `Spec:` lines with text after the first token. They are separable only by an unstated predicate, such as "value starts with `docs/`" or "first token is path-shaped". If that line is the lone final-block line, git even reads it as a trailer. If it sits mid-body, Expected would demand an "outside the block" hint.
- Fix: define the "Spec-shaped" predicate exactly and the precedence when several causes apply. Add fixtures that sit on each side of the boundary.
- Gap category: look-alike-negative-fixture; contradiction between Expected and an AC. Class: spec.

**2. R: AC-6's second half has no fixture (README:64, References:25).**
- "The trailer parser exits non-zero" cannot be produced by a real commit. I tried `trailer.where=bogus`, `trailer.ifexists=bogus` and an empty `trailer.separators`; all exit 0 with only a warning.
- The AC needs a stated mechanism, such as a PATH-shim `git`, or monkeypatching `subprocess.run` for a unit test of `git_trailers`.
- If a monkeypatch is used, say plainly that it tests the `returncode` check and not git.
- Class: test.

**3. H: the design does not say what happens to `body` after the strip is removed.** `body` also feeds `is_real_revert(body)`, `REVERTS` and `startswith("Revert ")`. State whether the cleaned body stays for those uses and only the trailer parse gets the raw file.

**4. H: the hint scan must look only above the scissors line.** A `-v` diff containing `+Spec: …` lines would otherwise raise false hints. The hint is advisory only, but add a fixture.

**5. H: `core.commentChar` is not mentioned.** Passing the raw file to git handles it, but pin it in an AC or fixture so a custom comment character does not regress.

**6. H: AC-2's fixture should be a real `git commit -v` with an editor stub.** The envelope row's own pointer "AC-2 replays it" is fine; make the fixture explicit and not a hand-built file.

**Dispositions.** The rejections hold.
- Subject-only `Spec:`: git returns no trailers, so it is rejected through the plain message.
- In-block `Spec:` authoritative, and non-source commits exempt: consistent with the code, where an exempt commit only checks a trailer that is present.
