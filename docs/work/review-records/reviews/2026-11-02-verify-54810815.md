FR-8 puts a verify-of-code record in the code class and requires the source diff "between the record's `commit` and the tree". So a verify record has no `commit` field. The gate must then either refuse every post-fix-first code ship (a legitimate flow wrongly refused) or skip the source binding for verify records (a ship with unreviewed source wrongly allowed).

Failure scenario:
- A code review returns fix-first.
- The fix lands.
- A verify review of the fix passes.
- The ship has no commit to diff against.

This is the very flow the ADR requires. No AC covers it. AC-5 and AC-7 test a verify record only at the lock edge. AC-6's "verify record of a code-class record" is a lock refusal.

Fix: a verify of a code record requires `REVIEWED-COMMIT` (and the record stores it). A verify of a design record must not carry one. Add an AC for the code-fix ship.
