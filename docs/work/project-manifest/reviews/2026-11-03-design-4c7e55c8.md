## Breaking
1. The tier source is circular and fails open (README "Derived" row, :152, :117, AC-3, AC-8, AC-9). R, breaking: yes,
   unconstrained-fallback / silent-default, design. deploymentTier is derived from the profile and P4 removes the
   CLAUDE.md and STATE.md tier lines, so "missing manifest falls back to the tier's profile" has no tier left;
   head_live() (spec_gate.py:107-110) and live_of return not live on absence. Scenario: P4 strips
   `deploymentTier: live` from D:/repo/SaaS/cashcow/CLAUDE.md:11; later the manifest is deleted, unparseable at HEAD,
   or written as `yolo`; the fallback is `yolo`, `live` disappears, a T1 locks without the live review. No AC pins it
   (AC-8 checks validity only; AC-9 judges items; AC-3 has no missing-manifest fixture; the Security row cites AC-5,
   the guard). agentic-loop AC-3 presumes the tier as an independent input. `public`'s tier undefined. Fix: decide
   stored vs derived; fail closed (a repo that ever held live stays revenue, or the gate refuses); AC old tier <= new
   for all 28 repos with cashcow named; the gate compares HEAD's manifest with the staged one (FR-3 precedent).
2. P3 cannot be owned by this item (README:116, AC-6, AC-7, Assumptions row 3). R, breaking: yes, cross-repo
   ownership, design. Foreman and Catwalk are separate repos with their own docs/work items and gates; a source commit
   there needs a Spec trailer naming an item in that repo; AC-6/AC-7 would run node and Foreman from a claudence
   Python test; Foreman has no YAML dependency. Split P3 into child items per repo; claudence owns schema, fixtures
   and merge rules (or consumers call `fleet config --json`, removing AC-6); keep repos.json as a generated cache.
