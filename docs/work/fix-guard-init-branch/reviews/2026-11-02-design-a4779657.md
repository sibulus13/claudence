## 2. fix-guard-init-branch

**1. R: "use the stripped command" regresses quoted targets and wrapper shells, and no AC covers either (README:24, 63; guard.py:140, 164).** The spec builds the target from `cmd`, where `QUOTED.sub("''", …)` has already replaced every quoted string with `''`. I ran the current functions on both forms:

| Command (cwd `D:/repo/Lib`) | Target from raw text (today) | Target from stripped text (proposed) |
|---|---|---|
| `git init "D:/repo/bad"` | `D:\repo\bad` (denied) | `D:\repo\Lib` (allowed) |
| `git init "D:/repo/Lib/my proj"` | correct | wrong path |
| `git clone URL "D:/repo/bad"` | `D:\repo\bad` (denied) | `D:\repo\Lib` (allowed) |
| `bash -c "git init D:/repo/bad"` | `D:\repo\bad` (denied) | `None` (allowed) |
| `powershell -Command "git init D:/repo/bad"` | `D:\repo\bad` (denied) | `None` (allowed) |

- Quoted absolute paths and `pwsh -Command "…"` wrappers are common on this machine.
- The fix as written turns working detection into false allows. AC-6 pushes the implementer toward stripping everything.
- Fix: detect the command position on the stripped text but read arguments from the raw text, or tokenise the raw text with a quote-aware parser. Add negative fixtures for a quoted target, a quoted `-C`, a quoted `cd` argument, and an explicit decision on `bash -c`, `pwsh -c` and `cmd /c`.
- Gap category: look-alike-negative-fixture, with a regression introduced by the fix. Class: design.

**2. R: AC-5 collides with an existing pinned test, and the spec does not say how it supersedes it (README:25, 62).** `tests/test_guard.py:134` asserts `not _bad_repo_target("D:/repo")`. The docstring on line 131 reads "fleet-docs-home/AC-9: ... the root itself is still not a target". Changing `bad_repo_target` as References row 3 says will turn that locked AC red, and the work item never mentions it. Either decide which contract holds and say so, or leave `bad_repo_target` alone and add a separate root check in the init/clone path. Class: design.

**3. R: the command-segment separators are unspecified, and AC-4 covers only `&&` (README:23, 61).**
- The guard serves both the Bash and PowerShell tools. Separators in play: `;`, `||`, `|`, `&`, newline, subshells `( )` and `$( )`.
- AC-4's second case uses `&&` only. An implementation that splits only on `&&` passes it while `git init D:/repo/Lib/x; git init D:/repo/bad` and a newline-separated variant still bypass the guard.
- The `cd` handling is also open: `pushd`, `Set-Location`, `cd ..`, `cd -`, `cd ~`, `cd $X`. Say what happens when the directory is not statically known. Deny, to match the "unparseable denies" rule, or the same allow bug returns.
- Fix: list the separators, `cd` variants and the unresolvable-`cd` outcome, and add fixtures for `;` and newline.
- Class: design.

**4. R: AC-6's `echo git init D:/repo/x` is not fixed by stripping alone (README:63).**
- That text is unquoted, so it survives `QUOTED` and `HEREDOC`. Today it is denied as an init.
- Passing it requires anchoring `git` at command position (start of a segment, optionally after `FOO=1`, `&`, `(`). The root cause and References never state that.
- The same anchoring determines `git.exe`, `/usr/bin/git`, `command git` and `& git`. Specify it.
- Class: design.

**5. H: the Expected line says "non-theme folders are denied", but `bad_repo_target` allows any `D:/repo/<X>/<y>` that is not legacy or `web`.** For example `D:/repo/Foo/x` is allowed. The ACs cover only `D:/repo/<one-segment>`. Clarify the Expected line so it does not invite widening.

**6. H: AC-1 and AC-2 say "targets X", but test_guard.py's `run()` observes only allow or deny.**
- The `--template D:/t D:/repo/Lib/x` case is allowed today by accident, because `D:/t` is outside the root.
- Require the tests to assert the computed target. The deny message already includes it; for allow cases, call `clone_or_init_target` directly.
- Also state the cwd for the first two AC-3 cases.

**7. F: option-parsing edge cases the ACs do not pin.**
- Attached short values (`-bmain`), `--` separators, and git's unambiguous long-option abbreviations (`--bra dev`) can make a value read as the target.
- Global options with separate values (`--git-dir X init`, `--work-tree`) make `X` read as the subcommand. Relative and chained `-C` are also unspecified.
- Unlikely from an agent that is not adversarial, so F.

**8. H: AC-7 does not scope the "unparseable" denial.** It could deny any command with a stray apostrophe, or only commands containing `git init` or `git clone`. State which.

**9. H: the rejected row "known limits logged in the guard's docstring at build" has no AC.** The rejection reasons for `//?/` paths, variables and `--separate-git-dir` are acceptable.
