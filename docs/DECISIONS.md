# Decisions — claudence (`~/.claude`)

ADR-lite journal for this repo. One row per decision.

**status** — `assumed` (a default chosen to keep moving; safe to change) · `confirmed` (owner-ratified) · `superseded` (with pointer).
**revisit-when** — the trigger that should re-open it.

| id | date | decision | status | rationale | revisit-when |
|----|------|----------|--------|-----------|--------------|
| D1 | 2026-08-16 | Restored WezTerm panes are placed by an explicit `Set-Location`, not by WezTerm's spawn-time `cwd` field | confirmed | `MuxWindow:spawn_tab{cwd=...}` is ignored on the `gui-startup` path (verified in an isolated instance); `MuxPane:split` honours it. Relying on the field made left-pane placement silently wrong. | A WezTerm release fixes `spawn_tab` cwd — then the `Set-Location` becomes belt-and-braces, not load-bearing |
| D2 | 2026-08-16 | A `claude --resume <id>` recipe is validated at **both** save and restore | confirmed | The pane→session binding can be stale (pane ids recycle every relaunch) *and* the transcript can be reaped between save and restore. Validating only at save left the on-disk recipes poisoned. | Claude exposes a first-class "does this session exist" query — replace the filesystem probe with it |
| D3 | 2026-08-16 | Keep the `explanatory-output-style` plugin enabled; resolve its conflict with the Terse-Output Contract by precedence, not removal | assumed | The two collide on length only, not on substance. Precedence keeps the educational depth while moving it out of the terminal into this repo's docs. | Terminal responses stay long despite the precedence rule — then disable the plugin in `settings.json` → `enabledPlugins` |
| D4 | 2026-08-16 | Docs root is resolved per session by `scripts/resolve-docs-root.ps1`, defaulting to the nearest ancestor holding `.git` | confirmed | Pooling every project's session log into `~/.claude/docs` mixes unrelated version-control histories. Nearest-`.git` gives per-project segregation for free; the marker file and the registry exist for the case it cannot decide (a workspace nested inside a larger repo, e.g. `Life/pylon` inside the `Life` repo). | A workspace needs a docs root the six rules cannot express - then add a rule rather than another override layer |
| D5 | 2026-08-17 | Projects that are not their own git repo are listed in an explicit `EXTRA_PROJECTS` table, not discovered by a rule | assumed | Loosening `discover_repos()` (dropping the `_Misc`/`archive` prunes, or treating any directory as a project) would add ~30 rows of take-home tests and dead archives to a launcher that is supposed to be a short list. A curated table keeps the signal high; the cost is that a new sub-project must be added by hand. | The table needs edits more than about once a month, or a `Life` sub-project is missed in practice — then key on a marker file (e.g. `.claude-docs-root`, already present in several) instead of a list |
| D6 | 2026-08-17 | Launcher rows carry the product name alongside the path (`Crucible · Stock/Research 2026`); `REPO_ALIASES` is no longer tab-title-only | confirmed | The folder name and the product name diverge for four projects, and the fuzzy launcher only ever matched the folder. Showing both means either spelling finds the row, at the cost of a slightly longer label on four rows. | A repo is renamed to match its product name — then drop its alias row rather than keeping a redundant label |
| D7 | 2026-08-17 | `tests/run-tests.ps1` globs `*.tests.ps1` instead of enumerating files | confirmed | The hardcoded manifest would have silently skipped a newly added suite while still printing a green gate — the same failure mode as the launcher's hardcoded discovery. An empty glob now fails rather than passing vacuously. | A test file needs to be excluded from the gate — then name the exclusion explicitly rather than reverting to a manifest |
