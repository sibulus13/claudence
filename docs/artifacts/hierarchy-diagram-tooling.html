Drawing hierarchies you can click into

Split out of the Envisio system map, where it did not belong. The question was whether a component system exists for drill-down diagrams — a high-level view that expands into its own detail, nested several layers deep. Several do, and they split cleanly by whether the hierarchy is the point, or the graph is.

Scope This page is method, not company knowledge. Envisio product briefs live in their own set and stay free of technique, so a reader opening one never has to sort the two apart.

The options, and what each actually buys you

OptionWhat it gives youReach for it whenCost
LikeC4likec4 Architecture defined as text in a DSL, compiled into a navigable site where clicking an element drills from context into container into component. Drill-down is the native interaction, not an add-on. You want the map to be the durable, diffable source of truth that survives the next re-org. Closest thing to a finished product for this exact need. A DSL to learn; opinionated about C4 levels
StructurizrDSL + C4 model The original model-once-render-many approach. One model, many views at different altitudes. Mature, well documented, hosted and self-hosted paths. You want the C4 methodology with the widest ecosystem and don't mind heavier tooling. Heavier; the free renderer is plainer
React Flow@xyflow/react A controlled node-and-edge canvas with working pan and zoom, custom node components, and sub-flows for nesting. You own the expand logic; every primitive is there. The diagram must live inside a React app. Sub-flows map naturally onto any nested domain model. You implement collapse yourself; pair with elkjs or dagre for layout
d3-hierarchyD3 The canonical layouts — collapsible tree, treemap, sunburst, partition, icicle. The collapsible tree is the reference implementation of drill-down. The data is genuinely a tree and you want a real layout algorithm rather than indentation. Most code to own; no React bindings
visx@visx/hierarchy D3's layout maths exposed as React components. You keep React's rendering and state model. Middle ground — D3 layouts without hand-writing enter/update/exit. Lower level than a charting library; you compose it
Cytoscape.js+ expand-collapse Compound nodes with native collapse, built for large graphs. Handles thousands of nodes where the others degrade. Scale is the problem — a full dependency graph rather than a curated map. Plainer defaults; imperative API
Mermaidtext to SVG Excellent in docs and pull requests. Its click directive fires a callback, but there is no expand/collapse model. Docs-as-code, where a static picture in a Markdown file is the goal. Wrong tool for interaction — this was the original mistake
tldraw / Excalidrawfreeform canvas Embeddable, pleasant, good for thinking out loud with a group. Whiteboarding, not documenting. Not model-driven, so it drifts the moment the system changes

What I would actually reach for

Three calls

For an architecture record that must stay true: LikeC4. It is text, it lives in the repo next to the code, it diffs in a pull request, and drill-down navigation is built in rather than assembled. That directly fixes the failure mode every hand-maintained diagram has — quietly going stale while still looking authoritative.

For anything shipped inside a product: React Flow. MIT licensed, real pan and zoom, and the sub-flow primitive handles nesting without you writing a layout engine.

For a one-off page where the shape is genuinely a hierarchy: hand-roll it. The Envisio system map is about 120 lines of vanilla JS over a nested JSON array. A disclosure tree is the one case where a library buys almost nothing and costs you a build step — and because the diagram is the JSON, editing it is editing data, not markup.

Two constraints worth knowing before you choose

  • Published artifacts run under a strict CSP with no external hosts. No CDN scripts, fonts or images — anything from the table above has to be bundled and inlined. That is a real reason to hand-roll inside an artifact, and no reason at all to avoid these libraries inside an app that has a build step.
  • A tree is the wrong shape for two common cases. A system context is a graph with cycles, and a sequence has a time axis. Both want a static diagram, and neither should get fake zoom controls bolted on — a CSS transform over an SVG is not zoom, it is a scaling bug waiting to be reported.
