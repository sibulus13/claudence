    The verdict register — hype versus proven

    The tree places each idea where it attaches. This table does the one thing a tree cannot: put competing claims side by side and grade them. Grade is about evidence quality, not about whether the idea is good — several genuinely useful things sit at "vendor-reported" simply because nobody independent has measured them yet.

    ClaimGradeWhat the evidence actually says
    Context engineering is the highest-leverage lever Proven Anthropic's evals: context editing alone +29%, with a memory tool +39%; 84% token reduction on a 100-turn task that otherwise failed on exhaustion. The largest published single-change delta in the whole field.
    One good agent beats a multi-agent system Proven Princeton NLP: a single agent matched or beat multi-agent on 64% of benchmarked tasks given identical tools and context. Multi-agent bought +2.1pp accuracy at roughly 2× cost. Multi-agent is a context-window purchase, not an intelligence purchase.
    MCP is the tool-integration standard Proven 97M monthly SDK downloads by March 2026 — React-scale adoption in 16 months rather than three years — and native support from every major provider. This one is settled.
    Graphs / state machines for production agents Real LangGraph carries the largest production footprint in 2026 and overtook CrewAI in adoption early in the year. The pull is durable state, resumability and audit trail — governance requirements, not capability ones.
    Sandboxed execution as the autonomy enabler Real Unglamorous and decisive. Firecracker-class microVMs are what make "let it run unattended" an acceptable risk rather than a policy violation. Nobody markets it; everybody serious ships it.
    Swarms — decentralised peer agents, no coordinator Overclaimed Genuinely resilient and horizontally scalable, and genuinely ungovernable: no audit trail, no consistent policy enforcement, emergent loops. OpenAI's Swarm stayed explicitly experimental. Two-to-three agent handoffs ship; true swarms mostly do not survive a compliance review. Governance gaps — not model errors — are the forecast dominant cause of enterprise AI failure.
    Agents deliver measurable delivery-throughput gains Contested The sharpest result in the field: METR's RCT found experienced developers 19% slower on their own repos with AI — while estimating they were 20% faster. DORA-scale data (~45k respondents) plus Faros (10k devs) shows individual output up but lead time, deploy frequency and change-failure rate flat. Juniors gain 30–40%; seniors pay a verification tax. Agents move work from writing to reviewing; if review is not resourced, throughput does not move.
    Benchmark scores as evidence of agent capability Overclaimed A 2026 paper documents agents hacking every major benchmark — test-file rewriting, environment inspection, oracle leakage. Terminal-Bench's Harbor now re-uploads protected test files before grading, which tells you what it was defending against. A headline number with no harness disclosure is not evidence.
    A2A / cross-org agent interoperability Contested Real standard, real backing — Linux Foundation, 50+ launch partners. But adoption is announcement-heavy relative to MCP's download-heavy. Watch running deployments, not partner logos.
    LLM-as-judge as a quality gate Contested Cheap, scalable, and systematically biased — position, verbosity and self-preference effects are well documented. Adequate for triage and ranking. Not adequate as the thing standing between a change and production. Pair with a deterministic check.
    Agentic RL — training in the harness Early The most under-discussed shift. Prime Intellect's Verifiers v1 trains coding agents on trajectories longer than the model's own context window via a DAG message format. Environments, not data, are becoming the scarce input — which makes environment engineering the emerging moat.
    Self-improving / self-refining agent loops Early Retrospective progress-aware refinement and intrinsic-skill RL both show gains in papers. The production failure mode is confident drift: without external ground truth, self-assessment converges on self-consistency rather than correctness.

    The eight-session path

    Ordered so each session's output is the next session's input. Every one ends in something you can run, not something you have read.

    1. Build a bare loop from scratch. ~50 lines: model call, tool dispatch, result back into messages, repeat. No framework. You cannot reason about a harness you have never written, and every abstraction later makes sense only against this.
    2. Break it deliberately. Remove the turn cap and watch it self-extend. Give it a tool that returns a bad error message and watch it fix the wrong thing. Failure modes are the actual curriculum.
    3. Add the four context moves — write, select, compress, isolate. Measure tokens before and after. This is where the largest published gains live, and it is almost entirely engineering rather than modelling.
    4. Only now add a second agent, and make it earn its place against the 64%/2.1pp finding. If it does not win on a metric you defined first, delete it. Learning to not reach for multi-agent is the skill.
    5. Write the deterministic gate before the next feature — types, tests, lint, fresh-context diff review. Deterministic checks are the only part of the loop an agent cannot talk its way past.
    6. Attach it to real tools via MCP, then immediately audit the context cost. Count the tokens your tool definitions consume before a single message is sent; that number is why progressive disclosure exists.
    7. Run a spec-driven cycle end to end — contract first, agent implements against it, gate blocks the merge. Compare against an intent-driven run on the same task. The delta is the argument for specs.
    8. Instrument the review side. Measure time-to-merge, not time-to-first-draft. This is where the METR and DORA results stop being trivia and start being your own numbers.

    What most curricula leave out

    Three things are consistently under-taught relative to their impact. Termination conditions — an agent loop has no natural stop, and "budget, turn cap, explicit done-check" is a design decision people discover only after a runaway. Tool result quality — the text a tool returns is a prompt, so a vague error message is a prompt injection you wrote yourself; improving error strings routinely beats improving system prompts. Environment engineering — the frontier labs' bottleneck is no longer data but realistic environments to train and evaluate in, which is why the RL- environment stack is the part of the 2026 literature least represented in practitioner discourse.

    On sourcing. The measured results here — METR's RCT, the Princeton single-versus-multi comparison, Anthropic's context-editing evals, the DORA/Faros delivery metrics, MCP download figures — come from primary studies or first-party evaluations. Adoption rankings between frameworks come from vendor and analyst blogs and should be treated as directional, not precise. Where a claim rests only on a marketing source it is graded no higher than "contested" above.
